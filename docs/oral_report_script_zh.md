# 口頭報告稿（新手版）

## 開場

大家好，今天我要介紹的是我們的會員資料庫系統。

我自己也是資料庫新手，所以我會用比較簡單的方式來解釋。這個專題主要是用來管理會員資料、繳費資料、活動資料，還有活動報名資料。

## 系統功能

這個系統主要有兩種使用者：管理員和會員。

- 管理員負責管理資料、處理繳費、查看報表。
- 會員可以被建立資料、繳費，還可以報名活動。

## 資料庫結構

我們的資料庫有五張表：

- `Member`
- `Payment`
- `SportsEvent`
- `EventRegistration`
- `Admin`

你可以把資料表想像成不同的盒子，每一個盒子都存不同類型的資料。

## 工作流程

首先，我們會先用 SQL 建立資料庫。

接著輸入資料。

之後資料庫會檢查這些資料是不是正確。

如果資料正確，就會被存進去。
如果資料錯誤，資料庫就會拒絕。

## 為什麼使用 Constraint

我們使用 constraint 來防止一些基本錯誤。

例如：

- email 必須像真正的 email
- 繳費金額必須大於 0
- SID 必須唯一
- 同一位會員不能重複報名同一個活動

## 為什麼使用 Trigger

我們使用 trigger，因為有些規則需要自動處理。

例如：

- 只要會員繳費，狀態就自動變成 `Active`
- 非 `Active` 會員不能報名活動
- 已經過期的活動不能報名
- 未來日期的繳費不能輸入

這就是 trigger 在我們專題裡很重要的原因。

## 為什麼使用 View

我們使用 view 來做報表。

這樣不用每次都重寫很長的 SQL 查詢，資料庫就可以直接把報表整理好。

例如：

- 會員清單報表
- 會員狀態報表
- 繳費報表
- 活動列表報表
- 活動報名報表

## 一句話總結

如果要用一句話來總結這個專題，就是：

**tables 負責存資料，constraints 負責保護資料，triggers 負責自動處理規則，views 負責顯示報表。**

## 結尾

總結來說，這個專題讓我們看到資料庫不只是儲存資料，它也可以自動檢查資料、執行規則，並且產生報表。
